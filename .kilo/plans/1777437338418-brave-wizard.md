# Plan: Fix P5.js Thumbnail Generation

## Problem
P5.js art pieces do not generate thumbnails when saved in studio.php, while Three.js and C2 work correctly.

## Root Cause
In `src/libraries/p5.js:322-350`, the `captureThumbnail` function accesses `this._p5Instance.canvas` directly. However, in p5.js, `canvas` is a `p5.Renderer` object (not an `HTMLCanvasElement`). The actual DOM canvas element is at `canvas.elt`. This causes the function to fail silently when manipulating canvas dimensions.

The other renderers (Three.js and C2) correctly access the HTMLCanvasElement:
- **Three.js**: Uses `this._canvas` directly (HTMLCanvasElement)
- **C2**: Uses `this._canvas` directly (HTMLCanvasElement)
- **P5.js**: Uses `this._p5Instance.canvas` which is a p5.Renderer object — **BUG**

Note: The `getCanvas()` method at line 382-388 correctly uses `canvas.elt`, proving this is an oversight in `captureThumbnail`.

## Solution

### Option A: Direct Fix (Recommended)
Fix `captureThumbnail` in `src/libraries/p5.js` to access `this._p5Instance.canvas.elt`:

```javascript
P5Renderer.prototype.captureThumbnail = function(width, height) {
    if (!this._p5Instance) return '';

    // Get the actual HTMLCanvasElement, not the p5.Renderer wrapper
    var canvas = this._p5Instance.canvas && this._p5Instance.canvas.elt
        ? this._p5Instance.canvas.elt
        : null;

    if (!canvas) return '';

    var originalWidth = canvas.width;
    var originalHeight = canvas.height;

    // Resize canvas for thumbnail
    canvas.width = width;
    canvas.height = height;

    // Trigger redraw at new size
    if (this._p5Instance.redraw) {
        this._p5Instance.redraw();
    }

    var imageData = canvas.toDataURL('image/png');

    // Restore original size
    canvas.width = originalWidth;
    canvas.height = originalHeight;

    // Trigger redraw to restore
    if (this._p5Instance.redraw) {
        this._p5Instance.redraw();
    }

    return imageData;
};
```

### Option B: Reframe
Don't generate thumbnails client-side. Instead, capture thumbnails server-side using a headless browser or create a minimal "thumbnail mode" that renders to a small off-screen canvas. This is more complex but could provide better consistency across libraries.
